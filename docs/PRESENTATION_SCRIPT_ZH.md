# 五分钟演示讲稿

先在本地执行 prepare_demo.py，再用浏览器打开 data/presentation/index.html。幻灯片使用当前本地数据，不背诵旧截图中的数量。

**第 1 页（30 秒）**：本项目把 Westminster 公开规划申请转成建筑工种潜在线索。我从零实现了采集、存储、规则分类、摘要和增量同步。当前可用来源是 GLA London Planning Datahub，而不是声称已经直接抓通 council 门户。

**第 2 页（30 秒）**：客户不需要浏览整份规划登记册，而需要与自己工种和区域相关的少量批准申请。但批准只是信号，不表示马上开工，也不等于可以直接营销。

**第 3 页（40 秒）**：展示当前真实数量和来源。解释已验证日期与收到日期不同，Datahub 有同步延迟。打开一条原始 JSON 和一份 Markdown，显示字段、编号及来源时间。

**第 4 页（50 秒）**：讲清首次历史采集与后续增量：查询上次成功同步后更新时间变化的申请，包括更早的旧申请。重复编号不新增；内容变化更新；只有来源时间变化不重新分类。失败保留上次进度。展示一份实际 incremental 报告；0 条变化不等于数据库空了。

**第 5 页（50 秒）**：展示 Roofing 摘要，演示区域或半径筛选。说明独立 LBC、追认和条件变更的保守筛选，联系人缺失时回官方门户，不编造名字或电话。工种数量有交集，不能相加作为客户总量。

**第 6 页（50 秒）**：展示自动测试、审计，以及人工标注界面。明确 0.75 是规则分数，不是 75% 准确率。若还没完成独立标注，就说目前尚无真实 F1；如果已完成，展示实际 evaluation.json，并说明样本量和是否 held-out。没有真实 API 调用就不能把 mock 测试称为 LLM 成功。

**第 7 页（50 秒）**：展示 GitHub Actions 配置/实际运行状态，两者分开讲。说明状态缓存并非永久备份、原生告警依赖账户通知设置。下一步是独立评测、council 对照、商业使用条件和用户反馈。

## 可能被问到的问题

- 为什么不用 council 门户？当前环境请求返回 503；公开 Datahub 提供结构化真实元数据。我们没有绕过登录或访问挑战。
- 怎么防止重复？SQLite 主键去重、同步检查点、重叠时间窗口和内容变更检测。
- 数据准确吗？已验证导入与 Datahub 一致；独立 council 对照仍待门户可用，工种准确率另需人工标注。
- 有没有 AI？规则模式已经跑通；OpenAI 适配器和单条 smoke 命令齐备。只有真实调用报告存在时才能说 live LLM 已验证。
- 可以上线卖吗？当前是可演示原型；还需数据许可、联系人/隐私、独立质量评测、认证和持久存储。
- 下一家 council 怎么扩展？共用存储、分类、评估和摘要层；替换来源适配、字段映射、政策核查。
